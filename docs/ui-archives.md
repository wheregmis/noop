# Archived records

**Settings → Archive** lists removed routines, members, projects and plans. Filtering and pagination keep older copies accessible. Preview shows the saved record, conflicts and restore defaults. Press **Restore paused** for a routine or **Restore** for another record to authorize restoration. The archived copy stays intact, and an existing ID or project folder binding is never overwritten. A changed archive digest requires a fresh preview.

Restored routines are paused, including when an old Settings override would have enabled them. Members retain their profile, memory and supported files; current tool and autonomy settings apply because deleted overrides are not reconstructed. Projects restore their configuration and instructions; their actual folders are not copied or removed. A remote project needs a fresh folder check on the selected machine, and uses that check's current repository and detected requirements. Restored plans retain terminal history and do not start work or resume scheduling.

Archive keys identify supported records, rather than accepting arbitrary paths. Linked or unsupported archive files are rejected. Preview reports conflicts so an owner can resolve them before restoring; it does not silently replace another active record.

Restore uses a stable `request_id`. A failed publication returns the same record identity and `saved_locally: true`. **Check saved restore** confirms an existing receipt, while **Retry same restore** can publish or check that same request. Closing the preview or navigating away retains the pending request. A prepared authorization alone does not prove restoration: if no matching installed record can be verified, that request remains uncertain and cannot create the record again. **Inspect current record** checks what exists without claiming success. A fresh preview and explicit new action are required to restore again. **Refresh preview** warns before abandoning an unconfirmed request.

A completed receipt remains historical: replay cannot recreate a record that the owner deliberately deleted later. **Open restored record** checks its current state; confirmation describes the earlier restore, not a guarantee that nobody changed or removed it afterward.

Project confirmation can use `confirm_only: true` with the original key, digest, request identity and selected host/path. It checks an existing receipt without a fresh folder probe, so a lost reply can be recovered after that machine goes offline. A missing receipt fails without applying a restore.

The primary serves `POST /api/archive` for filtered lists, `POST /api/archive/preview` with `{key}`, and `POST /api/archive/restore` with `{key, digest, request_id, confirm_only?, project?}`. Project input contains `{host, path, probe_ticket?}`; folder proof is attached separately by the cloud hub after checking its owner, machine and requested path. Publication recovery may use a new transport ticket while retaining the restore request identity. An original partial reply remains unchanged.

`cloud/test/archive-records.ts` verifies all four kinds against the production Worker with separate primary and worker RemoteFiles mirrors. It checks immutable archive copies, paused routines, member memory, inert plan history, stale digests, collisions, unsafe keys and symlinks, lost replies, failed publication, historical replay after deletion, and fresh remote folder proof. Confirmation also succeeds after the fixture bridge withdraws project support and its folder is unavailable. The mirrors share a physical filesystem; no real user records, provider histories or model commands are used.
